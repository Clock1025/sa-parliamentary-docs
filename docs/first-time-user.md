# 第一次使用 committee-report

你提供條文與審查結果，AI 協助整理成對照表與審查報告。不需要先設定學校組織架構，也不需要安裝程式或設定 API。

## 先讓 AI 讀取 Skill

在 AI 開一個新對話，貼入 [START-HERE 的啟動提示詞](../START-HERE.md#可複製啟動提示詞)。ChatGPT、Claude 等環境若具備 GitHub 讀取能力，可以直接提供專案網址與 Skill 路徑，請 AI 先完整讀取再工作。能否讀取依當前環境而定，不能只憑平台名稱判斷。

| committee-report 原始檔案 | 用途 |
| --- | --- |
| [GitHub 檔案頁](https://github.com/Clock1025/sa-parliamentary-docs/blob/develop/skills/committee-report/SKILL.md) | 查看或下載完整 SKILL.md |
| [Raw 全文](https://raw.githubusercontent.com/Clock1025/sa-parliamentary-docs/develop/skills/committee-report/SKILL.md) | 全選複製純文字，從開頭 `---` 到最後一段 |

在 Gemini 或任何無法讀取 Repository 的環境，開啟上面的 Raw 全文，完整貼入對話；也可以下載完整 `SKILL.md`，用平台的附件功能上傳。若不接受 `.md`，改貼全文。請 AI 完整閱讀，若讀取失敗或內容截斷就明確告知，不得依記憶補完或假裝讀過。取得並讀完後，再提供下列材料。

本頁只說明操作，不另維護一份完整 Skill。也可使用 [獨立完整提示詞](../prompts/committee-report.md)作為備援。

## 會前：提供現行法規與草案

貼上或上傳現行法規及同一法規的各份修正草案，標明提案人與哪些是學生會案、哪些是議員案。可以分批提供，不需要一次整理成複雜表格。

AI 會整理各版本的會前對照表；請核對原文、提案歸屬、增訂、刪除與條次對應。檔案能否解析取決於環境，讀不到的內容不能靠猜測補完。

## 會中：直接輸入審查紀錄

用平常說話的方式記錄即可，例如：

> 第四條照甲案通過。第八條採乙案，十四日改七日。第十六條保留送大會。

不用逐條強制確認。指定案與修改位置清楚時，AI 可整理局部修正後的完整文字；不清楚的結果先列待確認。保留送大會不等於通過，新寫整條則由你提供全文。

## 會後：集中確認，再產生文件

告訴 AI「會議結束，請整理結果讓我一次確認」。核對各條的審查結果與完整文字，修正錯誤後確認本版，再請 AI 製作正式報告。

具備檔案產生能力的環境可依 Skill 製作可編輯 DOCX；PDF 優先從確認後的 DOCX 轉換，也需要指定字體與轉換能力。若當前環境不能產生或轉換，AI 必須明說，不能把文字回覆、假下載連結或其他格式冒充已完成的 DOCX／PDF。取得文件後仍應檢查條文、表格與跨頁版面。
